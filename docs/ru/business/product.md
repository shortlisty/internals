# Структура продукта

> **Аудитория:** Основатели, команда.
> **Назначение:** Объяснить, из чего состоит BENE в бизнес-терминах — приложение для тенантов, четыре функциональных столпа, концепция интерфейса и логика позиционирования. Читать перед архитектурным справочником.

---

## Что такое продукт

BENE Intelligence — это база знаний и рабочий инструмент для менеджеров мероприятий и event-агентств. Его задача — помочь им быстрее организовывать площадки, раньше находить нужную и проводить лучшие мероприятия — без ручной работы, которая сейчас всё замедляет.

У продукта один пользователь: event-профессионал. Всё построено вокруг его ежедневного рабочего процесса — получение документов о площадках, формирование библиотеки проверенных площадок, ответы на клиентские брифы и подготовка предложений. Конечный клиент (человек, заказывающий мероприятие) — получатель результатов этого рабочего процесса, а не пользователь инструмента.

---

## Приложение для тенантов

Продукт — единая рабочая среда: приложение для тенантов. Каждое event-агентство или менеджер мероприятий работает как тенант с собственной изолированной библиотекой, командой и настройками.

Приложение для тенантов утилитарно и быстро. Оно создано для ежедневного использования профессионалами, которым нужно решать задачи, а не для случайных посетителей, которым нужна пошаговая помощь. Плотность интерфейса — это функция: нужное количество информации на экране без перегруженных модальными окнами и мастерами потоков, которые замедляют опытных пользователей.

Концепция интерфейса: паттерны взаимодействия таких инструментов, как Akeneo PIM (редактирование структурированных данных на скорости, навигация в стиле сетки), OroCommerce (плотные, но удобочитаемые макеты, редактирование на месте) и pics.io (просмотр медиаактивов без трений, пространственные превью). Не корпоративная сложность — правильная плотность для профессионала, работающего в инструменте каждый день.

Всё в приложении для тенантов оптимизировано под два момента:

- **Ввод:** загрузить документ, внести данные, исправить результат извлечения, разрешить конфликт — как можно быстрее.
- **Поиск:** найти любую деталь о площадке во всей библиотеке — через запрос на естественном языке или фильтруемую таблицу — за секунды.

## Четыре функциональных столпа

Приложение для тенантов построено на четырёх функциональных кластерах. Каждый — отдельная область с собственной моделью данных и UX-поверхностью. Вместе они образуют полный рабочий процесс управления знаниями о площадках без внешних зависимостей.

### ETL и самоингест

Как данные о площадках попадают в систему. Менеджеры мероприятий импортируют из внешних источников — таблиц, выгрузок поставщиков, других баз — или вводят данные вручную, без привлечения IT. Основной путь — AI-извлечение из загружаемых документов. Ручной ввод и массовый импорт — запасные варианты.

Это точка входа. Без качественного ингеста библиотека остаётся пустой, а продукт теряет ценность.

Соответствует эпику: [E2 — Интеллект документов](../../roadmap/epics/E2-document-intelligence.md).

### PIM — управление информацией о продукте

Структурированное хранилище знаний. Вся текстовая и структурированная информация о площадке хранится здесь: названия и описания залов, конфигурации вместимости, политика кейтеринга, цены, доступные опции, контактные данные, ограничения.

«Продукт» в PIM — это «площадка» в BENE. Каждая площадка — структурированная запись со схемой. PIM-слой соблюдает эту схему, отслеживает провенанс (из какого источника пришло каждое поле), управляет оценками уверенности и разрешает конфликты при несоответствии данных из нескольких документов.

Это ядро платформы. Поиск, обмен и каждый последующий рабочий процесс зависят от качества данных здесь.

Соответствует эпикам: [E1 — Профили площадок](../../roadmap/epics/E1-venue-profiles.md), [E6 — Качество данных](../../roadmap/epics/E6-data-quality.md).

### DAM — управление цифровыми активами

Медиахранилище. Планы этажей, фотографии, видеотуры, 3D-туры, CAD-файлы, брендированные презентации — все бинарные активы, связанные с площадкой.

DAM в BENE Intelligence — не универсальное хранилище файлов. Активы привязаны к площадкам и к конкретным залам или пространствам внутри площадки. План этажа — это не просто файл: это пространственный актив, связанный с залом с известными размерами. Именно эта привязка делает актив поисковым и полезным, а не просто хранимым.

Соответствует эпикам: [E1 — Профили площадок](../../roadmap/epics/E1-venue-profiles.md) (субмодель активов), [E2 — Интеллект документов](../../roadmap/epics/E2-document-intelligence.md) (обработка планов этажей).

### Поиск

Слой поиска по всему PIM и DAM. Запросы на естественном языке, ключевой поиск, структурированные фильтры (вместимость, местоположение, тип кейтеринга, оборудование) и геопространственный поиск — все работают с одним структурированным хранилищем данных.

Поиск — это главное взаимодействие с продуктом. Менеджер должен иметь возможность описать клиентский бриф на обычном языке и получить ранжированный, с указанием источников шорт-лист, не открывая ни одного файла.

Соответствует эпику: [E3 — Поиск](../../roadmap/epics/E3-search.md).

## Резюме позиционирования

BENE занимает нишу, которую существующие инструменты не заполняют.

Универсальные файловые хранилища (Drive, Dropbox) хранят документы о площадках, но не могут их читать. Корпоративные DAM-платформы (Bynder, Brandfolder) управляют активами обобщённо — без схемы площадок и без извлечения. Маркетплейсы площадок (Cvent, VenueScanner) знают публично размещённые площадки, но не те, что есть в собственных файлах организатора. Универсальные AI-инструменты (ChatGPT) могут ответить на разовый вопрос по PDF, но не имеют памяти, схемы и командного доступа.

BENE объединяет ETL, PIM, DAM и поиск в едином приложении для тенантов, сфокусированном именно на рабочем процессе управления площадками. Это не универсальный инструмент, адаптированный под мероприятия — он создан с нуля для event-профессионалов, с плотностью интерфейса, которая нужна работающим профессионалам.
