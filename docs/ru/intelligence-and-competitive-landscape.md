## 1. Конкурентная среда

### 1.1 Платформы управления площадками и мероприятиями

Это устоявшиеся игроки. Ни один из них не является платформой _интеллекта документов_ — это операционные системы бронирования/CRM, которые начали прикручивать ИИ поверх структурированных данных, которые у них уже есть.

---

#### Cvent

**Что это:** Крупнейшая корпоративная платформа управления мероприятиями. 340K+ площадок в своей сети поставщиков.

**Сильные стороны:**

- Огромная база данных площадок (мост со стороны предложения)
- Автоматизация RFP (отправка брифа, получение структурированных ставок)
- Поиск и рекомендации площадок на основе ИИ
- Полный жизненный цикл мероприятия: поиск → регистрация → на месте → отчётность
- Глобальное присутствие, сильные корпоративные контракты

**Пробелы, релевантные для IQ BENE:**

- Cvent — это платформа _поиска и бронирования_ — она не помогает вам вести собственную библиотеку площадок
- Площадки в Cvent сами указываются владельцами площадок, а не извлекаются из ваших собственных документов
- Нет интеллекта документов (нет парсинга PDF/планов этажей/CAD)
- Нет командной базы знаний о площадках
- Корпоративные цены делают его недоступным для SMB-агентств

**Вердикт:** Не прямой конкурент. Cvent — маркетплейс площадок. IQ BENE — слой интеллекта для вашего собственного портфеля площадок. Они могут быть _дополняющими_ (импортировать найденные площадки из Cvent в IQ BENE).

---

#### Tripleseat

**Что это:** Программное обеспечение для продаж и кейтеринга для ресторанов, отелей и уникальных площадок. 20 000+ клиентов-площадок.

**Сильные стороны:**

- Сильные операционные рабочие процессы (бронирование, договоры, выставление счетов)
- Только что запустили «Tripleseat Intelligence» — пакет ИИ, построенный на их наборе данных из миллионов мероприятий
- ИИ для: прогнозирования спроса, рекомендаций запасов F&B, разговорной аналитики, бенчмаркинга среди коллег
- Глубоко встроен в операционные процессы гостеприимства

**Пробелы, релевантные для IQ BENE:**

- Tripleseat построен _для площадок_ для управления их мероприятиями — а не _для организаторов_ для управления их портфелем площадок
- Их ИИ работает на их собственных транзакционных данных (бронированиях), а не на неструктурированных документах
- Нет парсинга документов, нет кросс-площадочного поиска для организаторов
- Нет поддержки собственных загруженных организатором активов

**Вердикт:** Разные стороны рынка. Tripleseat обслуживает площадки; IQ BENE обслуживает организаторов. Архитектуры интеллекта принципиально разные: Tripleseat добывает структурированные операционные данные; IQ BENE добывает неструктурированные документы.

---

#### Momentus Technologies (ранее Ungerboeck / VenueOps)

**Что это:** Корпоративное управление площадками и мероприятиями. Обслуживает конгресс-центры, театры, стадионы, университеты. 700+ театральных центров, 50+ стран.

**Сильные стороны:**

- Сквозное: бронирование → операции → финансы → аналитика
- Улучшения платформы на основе ИИ (февраль 2026): операционные инсайты, оптимизация пространства
- 20+ лет интеллекта площадок и мероприятий, вшитые в их модели
- Продукт WeTrack для управления безопасностью/устойчивостью/рисками

**Пробелы, релевантные для IQ BENE:**

- Тяжёлый корпоративный продукт, недоступный SMB-агентствам
- Фокус на операторах площадок, управляющих своим пространством, а не на организаторах, курирующих портфель
- Нет интеллекта документов или ETL-конвейера
- Внедрение занимает месяцы, а не минуты

**Вердикт:** Корпоративное ПО для операций площадок. Нет пересечения с ядром интеллекта документов IQ BENE.

---

#### Perfect Venue / Planning Pod / Event Temple

**Что это:** Лёгкие инструменты управления площадками, нацеленные на независимые площадки, небольшие отели, винодельни.

**Сильные стороны:** Доступные по цене, лёгкие в настройке, покрывают основы бронирования.

**Пробелы:** Нет ИИ, нет интеллекта документов, нет концепции командной библиотеки площадок. Скорее CRM, чем интеллектуальная платформа.

**Вердикт:** Не имеют отношения к позиционированию IQ BENE. Совершенно другой ценовой/функциональный уровень.

---

#### VenueScanner

**Что это:** Британский маркетплейс площадок и консьерж-сервис. 19 000+ площадок по Великобритании и миру. Описан Forbes как «Airbnb аренды площадок». 1M+ организаторов мероприятий используют платформу ежегодно.

**Сильные стороны:**

- Большой самостоятельный поиск с фильтрами по местоположению, вместимости, цене и удобствам
- Бесплатно для организаторов мероприятий — модель дохода — комиссия от площадок
- VenueScanner для бизнеса: консьерж-команда обрабатывает корпоративные брифы, согласовывает тарифы, составляет шорт-листы за 24–48 часов
- Алгоритм ранжирования на основе ИИ повышает площадки, которые быстро отвечают на запросы
- Расширение за пределы Великобритании на международные рынки

**Пробелы, релевантные для IQ BENE:**

- Чистый маркетплейс _поиска и бронирования_ — площадки размещаются владельцами, а не извлекаются из документов, принадлежащих организатору
- Нет библиотеки площадок или базы знаний на стороне организатора
- Нет интеллекта документов — организаторы не могут загружать свои собственные PDF, планы этажей или спецификации
- ИИ ограничен ранжированием и оценкой времени отклика, а не семантическим извлечением
- Нет кросс-сравнения площадок против собственного портфеля организатора

**Вердикт:** VenueScanner — потребительская поисковая система площадок, а не инструмент интеллекта организатора. Организатор, который уже знает свои предпочтительные площадки, ничего не получает от VenueScanner — он помогает только с первым проходом обнаружения площадок, с которыми ещё не работал. Дополняет IQ BENE, не конкурирует.

---

#### VenueFindAI

**Что это:** Поиск и консьерж-сервис площадок на основе ИИ (venuefindai.com). Позиционирует себя как интеллектуальный помощник, который выдаёт персонализированные рекомендации площадок для корпоративных мероприятий и особых торжеств, при поддержке человеческих экспертов по требованию. Бесплатно для организаторов — без комиссий, без платы за услуги.

**Модель:** Сопоставление на основе ИИ с консьерж-слоем «человек в контуре». ИИ выдаёт рекомендации; человеческие специалисты доступны «по нажатию кнопки» для сложных или высокоценных брифов. Модель дохода, судя по всему, со стороны площадок (похоже на VenueScanner, Hire Space — площадки платят за лиды/размещение, а не организаторы платят за сервис).

**Сильные стороны:**

- Нулевая стоимость для организаторов — значительно снижает барьер к пробному использованию
- Гибридная модель ИИ + человек хеджирует против пределов точности чистого поиска на основе ИИ
- Широкий охват: корпоративные мероприятия и торжества, предполагающий широкий инвентарь площадок или намерение его построить
- Простое позиционирование, которое легко понять нетехническим покупателям

**Пробелы, релевантные для IQ BENE:**

- Платформа обнаружения: работает из базы данных площадок, _которые сами разместились_ — а не из документов, которые у организатора уже есть
- Нет базы знаний на стороне организатора — рекомендации эфемерны, не хранятся как командный актив
- Нет интеллекта документов, нет ингеста PDF/планов этажей, нет структурированного извлечения
- Человеческий консьерж-слой добавляет задержку и не масштабируется на полный портфель организатора из 50–100 известных площадок
- Рекомендации ИИ настолько хороши, насколько хороши самостоятельные указания площадок — в тот момент, когда организатору нужен интеллект из его собственных файлов (презентация площадки, присланная по email, план этажа из 2019), у VenueFindAI ничего нет

**Вердикт:** Та же четверть, что и VenueScanner и Cvent — маркетплейс/инструмент поиска площадок для _обнаружения_ новых площадок. IQ BENE решает смежную и дополняющую задачу: когда вы нашли и поработали с площадками, как вы управляете, извлекаете интеллект и ищете по всему, что вы уже знаете о них. Организатор может использовать VenueFindAI, чтобы обнаружить площадку, затем использовать IQ BENE, чтобы ингестировать документы этой площадки и построить постоянный, искомый профиль.

---

#### VenueArc

**Что это:** SaaS-платформа бронирования площадок и управления мероприятиями, построенная специально для театральных центров, театров и площадок живых мероприятий. Охватывает календари бронирования, договоры, расчёты, CRM и финансовую отчётность.

**Сильные стороны:**

- Специализация на операторах площадок искусств / живых мероприятий
- Календарь бронирования с предотвращением конфликтов, удержанием мероприятий, динамическим планированием
- Генерация договоров, портал расчётов, финансы и отчётность
- Интеграция с Ticketmaster / Nexus для данных живых мероприятий
- CRM с видимостью данных клиентов и захватом лидов
- Облачный, среднерыночные цены

**Пробелы, релевантные для IQ BENE:**

- Обслуживает _операторов площадок_, а не организаторов мероприятий — то же различие сторон рынка, что и у Momentus и Tripleseat
- Нет интеллекта документов, нет ингеста PDF/планов этажей, нет ETL-конвейера
- Нет управления портфелем для организаторов
- Узкая вертикаль: театральные центры и театры, а не более широкий рынок корпоративных/социальных мероприятий

**Вердикт:** Нишевое операционное ПО для площадок для конкретной вертикали (искусство). Нет пересечения с основным вариантом использования IQ BENE. Ближе к облегчённой версии Momentus, чем к чему-либо из конкурентного набора IQ BENE.

### 1.2 Платформы управления цифровыми активами (DAM)

DAM-платформы — это ближайшая смежная категория к IQ BENE: они централизуют, тегируют, ищут и распространяют цифровые файлы для маркетинговых и бренд-команд. В отличие от инструментов бронирования/CRM выше, DAM действительно работают с неструктурированными файлами (изображениями, PDF, видео). Но их интеллект построен для управления брендом, а не для интеллекта площадок.

---

#### Bynder

**Что это:** Одна из крупнейших корпоративных DAM-платформ. В первую очередь обслуживает маркетинговые, бренд- и креативные команды в крупных организациях. Используется глобальными брендами для управления логотипами, изображениями кампаний, документами и видеобиблиотеками.

**Сильные стороны:**

- Централизованная библиотека активов с богатыми метаданными, таксономией и контролем версий
- Агенты ИИ (2025+): автоматическое обогащение метаданных, генерация заголовков/описаний/тегов при загрузке
- Встроенные руководства по бренду, стайл-гайды и рабочие процессы согласования
- Динамическое преобразование активов: изменение размера изображений на лету, преобразование форматов, доставка через CDN
- 250+ интеграций (Adobe Creative Cloud, Canva, Salesforce, CMS-платформы)
- Поддержка нескольких порталов: ролевые бренд-порталы для разных команд или клиентов
- Сильная корпоративная соответствие: SOC 2, SSO, гранулярные разрешения

**Цены:** Только по запросу. Входной уровень около $450/месяц; корпоративные контракты в среднем ~$41K/год по данным закупок.

**Пробелы, релевантные для IQ BENE:**

- Построен для _бренд-активов_ (логотипов, изображений кампаний, маркетинговых документов) — а не интеллекта площадок
- Нет схемы извлечения, специфичной для площадок (нет вместимости, удобств, конфигураций залов, ограничений)
- Обогащение ИИ является общим (автоматически тегирует любое изображение/документ) — нет предметного понимания планов этажей или спецификаций
- Нет конвейера парсинга документов, спроектированного для мультиформатных документов площадок из нескольких источников
- Нет семантического поиска против _извлечённых_ атрибутов площадок — только поиск по метаданным
- Нет кросс-документной агрегации или разрешения конфликтов
- Цены рассчитаны на корпоративные маркетинговые команды, а не агентства по организации мероприятий

**Вердикт:** Bynder — это сложная библиотека контента, а не интеллектуальная платформа. Если бы организатор хранил PDF площадок в Bynder, он получил бы организованное хранилище и общие ИИ-теги. Он бы _не_ получил извлечённые данные о вместимости, структурированные конфигурации залов или ответы на «найдите мне площадку с грузовым лифтом и кошерным кейтерингом». Слой интеллекта, предоставляемый IQ BENE, в любом DAM просто отсутствует.

---

#### Brandfolder (от Smartsheet)

**Что это:** DAM-платформа, приобретённая Smartsheet в 2020 за $155M. Теперь позиционируется как подраздел управления контентом рабочего набора управления Smartsheet. Обслуживает среднерыночные и корпоративные команды, ведущие бренд- и креативные активы.

**Сильные стороны:**

- Движок Brand Intelligence: собственные AI/ML для авто-тегирования, обнаружения объектов и умной классификации контента
- Поиск на естественном языке (в развёртывании): находить активы с помощью разговорных запросов вместо точных ключевых слов
- Умный CDN: публиковать и распространять активы напрямую в веб/социальные каналы
- Настраиваемые бренд-порталы для клиентского обмена активами
- Тесная интеграция со Smartsheet: согласовывать активы в Smartsheet, публиковать в Brandfolder в один клик
- 30+ готовых интеграций
- Чистый, современный UI — более низкая кривая обучения, чем у Bynder, для среднерыночных команд
- Обеспечивает Media Manager Getty Images (анонсировано февраль 2026) — обрабатывает высокообъёмную профессиональную ингестацию активов в масштабе

**Цены:** Кастомные, по запросу. Два уровня (Premium и Enterprise). Стартовая точка, сообщается, около $1,600/месяц; медианные контракты около $24,700/год.

**Пробелы, релевантные для IQ BENE:**

- То же фундаментальное ограничение, что и у Bynder: разработан для _бренд-/маркетинговых активов_, а не интеллекта площадок
- Brand Intelligence тегирует визуальный контент обобщённо — нет понимания специфичной для площадок семантики
- Нет структурированного извлечения конфигураций вместимости, политик кейтеринга, характеристик AV или геометрии планов этажей
- Нет агрегации из нескольких источников: загрузка трёх версий одной презентации площадки не разрешает конфликты
- Нет рабочего процесса организатора мероприятий: нет поддержки RFP, нет сравнения площадок, нет истории поиска
- Интеграция Smartsheet помогает с _управлением работой_ (задачи, согласования) — а не со знаниями о площадках

**Вердикт:** Brandfolder — сильнейший среднерыночный конкурент Bynder с более чистым UX и более сильной историей ИИ-тегирования. Ни один не является платформой интеллекта площадок. Организатор, использующий Brandfolder, получает хорошо организованную файловую библиотеку с хорошим визуальным поиском — и ничего более. Ниша, которую заполняет IQ BENE (структурированное извлечение, специфичное для площадок, семантический поиск по атрибутам площадок, согласование из нескольких источников), полностью отсутствует в категории DAM.

### 1.3 Инструменты производительности ИИ для профессионалов в сфере мероприятий

Отчётливая возникающая категория: помощники ИИ общего назначения, построенные специально для организаторов мероприятий. Это не базы данных площадок или системы бронирования — это инструменты автоматизации рабочих процессов, оборачивающие LLM в шаблоны задач, специфичные для индустрии мероприятий.

---

#### Spark (sparkit.ai) — от GEVME & PCMA

**Что это:** Платформа производительности ИИ для профессионалов в сфере мероприятий, построенная сингапурской event-tech компанией GEVME в партнёрстве с PCMA (Professional Convention Management Association) — ведущей глобальной ассоциацией индустрии бизнес-мероприятий. Запущена в середине 2023 как «Project Spark»; сейчас в версии 2.0 с 14 500+ профессионалов в 150+ странах.

**Сильные стороны:**

- 150+ предbuilt-заданий ИИ, охватывающих полный жизненный цикл мероприятия: построение повестки дня, биографии спикеров, текст email, описания мероприятий, названия сессий, анализ обратной связи, опросы, отчёты после мероприятия
- Spark 2.0 Agent Studio: no-code-конструктор агентов, который связывает несколько действий (веб-поиск → извлечение данных LinkedIn → генерация контента → вывод) в автоматизированные рабочие процессы
- DestinAItor: ИИ-модуль для исследования площадок/направлений, генерации ответов RFP и поиска направлений — нацелен на DMO и гостиничные отделы продаж
- Мультимодельный: работает по лучшим доступным LLM, а не привязывается к одному провайдеру
- Поддержка 30 языков
- Совместный брендинг с PCMA даёт ему значительную отраслевую доверие и дистрибуцию в сообществе бизнес-мероприятий
- Доступен бесплатный тариф; корпоративный тариф с SSO, пользовательскими интеграциями и контролями безопасности
- Spark Academy, Spark Excellence (командное обучение), SparkU (студенческий тариф): образовательная экосистема, встраивающая принятие

**Пробелы, релевантные для IQ BENE:**

- Spark — это инструмент _генерации контента и автоматизации рабочих процессов_ — он помогает организаторам писать быстрее, а не лучше знать свои площадки
- Нет базы знаний площадок: нет профилей площадок, нет хранимых документов, нет управления портфелем
- DestinAItor проводит исследования площадок из веб/публичных данных — он не ингестирует или не парсит собственные документы площадок организатора
- Нет интеллекта документов: нет парсинга PDF, нет извлечения планов этажей, нет поддержки CAD
- Нет структурированной схемы метаданных площадок — выводы это генерируемый текст, а не искомые структурированные данные
- Нет мультиисточниковой агрегации или разрешения конфликтов по документам

**Вердикт:** Spark — это ближайшее к специальному помощнику ИИ для организаторов мероприятий, и он хорошо принимается (14 500+ пользователей). Но это инструмент _написания и рабочего процесса_, а не _знаний_. Организатор, использующий Spark, может составить RFP быстрее — но всё ещё не имеет структурированной, искомой записи о том, что реально предлагают его 50 предпочтительных площадок. IQ BENE и Spark дополняют друг друга: Spark генерирует контент; IQ BENE поставляет интеллект о площадках, который делает этот контент точным и конкретным.

### 1.4 Платформы интеллекта документов и ETL

Это инфраструктурные игроки. Они — техническая основа, с которой конвейер IQ BENE либо конкурирует, либо может использовать.

---

#### Unstructured.io

**Что это:** Ведущая корпоративная ETL-платформа для неструктурированных данных. Целенаправленно построена для подготовки документов к LLM и RAG-конвейерам.

**Что делает:**

- Ингестирует: PDF, Word, PowerPoint, HTML, email, изображения, отсканированные документы
- Выдаёт: чистый, разбитый на чанки, готовый для LLM JSON
- Коннекторы: S3, SharePoint, Google Drive, Confluence, 25+ источников
- Назначения: векторные базы данных, хранилища данных
- Обрабатывает: OCR, извлечение таблиц, обнаружение вёрстки, многоколоночные PDF

**Цены:** Бесплатный тариф (15K страниц, без срока действия). Pay-as-you-go (~$2.66/вычислительный час). Корпоративная подписка.

**Значимость для IQ BENE:**

- Unstructured.io — это то, что слой ETL IQ BENE _мог бы использовать как бэкенд_ вместо построения с нуля
- Их библиотека с открытым исходным кодом (`unstructured`) может быть самохостящейся
- Обрабатывает самые сложные задачи парсинга (отсканированные PDF, многоколоночные вёрстки, таблицы)
- Не продукт для конечных пользователей — чистая инфраструктура/API

**Стратегический инсайт:** IQ BENE не должен заново изобретать парсинг документов. Unstructured.io (или Docling) обрабатывает слой извлечения. Добавочная стоимость IQ BENE — это _специфичный для площадок интеллект_ поверх него: предметная схема, модель агрегации, опыт поиска, командное сотрудничество.

---

#### IBM Docling

**Что это:** Набор инструментов преобразования документов с открытым исходным кодом от IBM Research Zurich, теперь под эгидой Linux Foundation AI & Data.

**Что делает:**

- Передовой анализ вёрстки PDF (модель DocLayNet)
- Распознавание структуры таблиц (модель TableFormer)
- OCR для отсканированных документов
- Экспорт: чистый Markdown, структурированный JSON с полными метаданными
- Обрабатывает: PDF, DOCX, PPTX, HTML, изображения
- Работает локально, без облачной зависимости, лицензия MIT

**Почему это важно для IQ BENE:**

- Бесплатный, с открытым исходным кодом, нет цены за страницу
- Превосходное понимание таблиц и вёрстки по сравнению с наивным парсингом PDF
- Прямая интеграция со Spring AI через `TikaDocumentReader` (под капотом Apache Tika) или кастомный `DocumentReader`
- IBM Granite-Docling-258M: новый сверхкомпактный VLM для преобразования документов в структурированный формат
- Идеально подходит для PDF с планами этажей, спецификаций с таблицами, многоколоночных презентаций площадок

**Стратегическое решение для IQ BENE:** Использовать Docling как основной слой парсинга документов. Он обрабатывает структурное извлечение (вёрстка, таблицы, текст), а ETL-конвейер Spring AI затем обрабатывает чанкинг, эмбеддинги и векторное хранение.

---

#### Apache Tika

**Что это:** Золотой стандарт экосистемы Java для обнаружения форматов файлов и извлечения текста. Обнаруживает и парсит 1000+ типов файлов через единый интерфейс.

**Что делает:**

- Извлечение текста из: PDF, DOC/DOCX, XLS/XLSX, PPT, изображений (через OCR), HTML, XML, ZIP и ещё 1000+ форматов
- Извлечение метаданных (автор, дата создания, размеры)
- Обнаружение языка
- Обнаружение MIME-типа
- Tika Pipes: отказоустойчивая, масштабируемая обработка (каждый файл в форкнутом JVM с лимитами таймаута/памяти)

**Интеграция со Spring AI:**

- Spring AI поставляет `TikaDocumentReader` из коробки
- `TikaDocumentReader` оборачивает Tika за интерфейсом Spring AI `DocumentReader`
- Обрабатывает: PDF, Word, Excel, PowerPoint прозрачно — тот же API независимо от типа файла
- Используется в продакшене для: индексации поисковых движков, анализа контента, конвейеров перевода

**Почему это правильный выбор для IQ BENE:**

- Проверенный в боях корпоративный Java на протяжении 15+ лет
- Поддержка DWG/DXF через AutoCAD-парсер Tika (прямой путь для CAD-файлов)
- Ноль дополнительной инфраструктуры — работает внутри процесса
- Tika Pipes для производственной безопасности (неправильные файлы не могут уронить сервис)
- Уже в ETL-конвейере Spring AI — нет необходимости в пользовательской интеграции

---

#### LlamaIndex / LangChain

**Что это:** Python-first фреймворки оркестрации ИИ. У LlamaIndex сильный парсинг документов (LlamaExtract, LlamaParse). У LangChain есть загрузчики документов.

**Значимость для IQ BENE:** Это инструменты Python-экосистемы. Поскольку IQ BENE — Java/Spring Boot, они неприменимы напрямую. Spring AI — это Java-эквивалент и быстро настигает.

**Примечание:** Если IQ BENE когда-нибудь понадобится Python-микросервис для специализированного извлечения (например, продвинутый анализ планов этажей), LlamaParse от LlamaIndex — лучший в своём классе для сложных PDF.

---

#### Reducto, Raydocs, Retab (стартапы интеллекта документов)

Недавние хорошо финансированные новички в сфере интеллекта документов:

- **Reducto** — $75M серия B (a16z, Benchmark, YC). Структурированное извлечение из сложных документов API-first.
- **Raydocs** — Извлечение на основе шаблонов с оценками уверенности и ссылками на источники.
- **Retab** — Pre-seed $3.5M. Нетехнические пользователи строят шаблоны извлечения.

**Паттерн:** Все эти компании — _горизонтальные_ API интеллекта документов. Возможность IQ BENE — быть _вертикальным_ — глубоко специализированным для документов площадок (планы этажей, презентации площадок, CAD-файлы, спецификации). Горизонтальные инструменты извлекают общие поля. IQ BENE извлекает интеллект, специфичный для площадок, с специально построенной схемой.

## 2. Архитектура ETL-конвейера — Проверенный фундамент

### 2.1 ETL-конвейер Spring AI

Spring AI поставляет первоклассный производственный ETL-конвейер с тремя компонуемыми стадиями:

```
DocumentReader  →  DocumentTransformer  →  DocumentWriter
   (Извлечение)           (Преобразование)            (Загрузка)
```

**DocumentReaders (Извлечение) — доступные из коробки:**

| Ридер                        | Обрабатывает                                     | Примечания                                               |
| ---------------------------- | ------------------------------------------------ | -------------------------------------------------------- |
| `TikaDocumentReader`         | PDF, DOCX, XLSX, PPTX, HTML, XML, 1000+ форматов | Под капотом Apache Tika. **Основной ридер для IQ BENE.** |
| `PagePdfDocumentReader`      | PDF, постранично                                 | Сохраняет границы страниц, полезно для планов этажей     |
| `ParagraphPdfDocumentReader` | PDF, на уровне параграфов                        | Лучший семантический чанкинг для презентаций площадок    |
| `MarkdownDocumentReader`     | Markdown-файлы                                   | Полезно для структурированных спецификаций площадок      |
| `JsonMetadataReader`         | JSON с метаданными                               | Полезно для структурированного импорта                   |
| `JsoupDocumentReader`        | HTML-страницы                                    | Веб-скрапинг информации о площадках                      |

**DocumentTransformers (Преобразование):**

| Трансформер                       | Что делает                                                                                               |
| --------------------------------- | -------------------------------------------------------------------------------------------------------- |
| `TokenTextSplitter`               | Разбивает большие документы на чанки с учётом лимитов токенов                                            |
| `ContentFormatTransformer`        | Нормализует формат текста                                                                                |
| `SummaryMetadataEnricher`         | Генерирует сводку документа с помощью LLM, хранится как метаданные                                       |
| `KeywordMetadataEnricher`         | Извлекает ключевые слова с помощью LLM, хранится как метаданные                                          |
| Кастомный `VenueMetadataEnricher` | **Специфичный для IQ BENE:** извлекает вместимость, удобства, контакты через структурированный вызов LLM |

**DocumentWriters (Загрузка):**

| Райтер               | Что делает                                     |
| -------------------- | ---------------------------------------------- |
| `PgVectorStore`      | Пишет чанки + эмбеддинги в PostgreSQL pgvector |
| `SimpleVectorStore`  | В памяти (тестирование/разработка)             |
| `FileDocumentWriter` | Пишет в файлы (полезно для отладки конвейера)  |

### 2.2 Конвейер обработки документов IQ BENE

```
                     Хранилище активов S3
                          │
                          │ загрузка по подписанному URL
                          ▼
               ┌─────────────────────┐
               │  DocumentReader     │  Spring AI / Apache Tika
               │  (по типу актива)   │  + IBM Docling (таблицы PDF)
               └──────────┬──────────┘
                          │  List<Document>
                          │  (чанки сырого текста + метаданные страницы)
                          ▼
               ┌─────────────────────┐
               │  DocumentSplitter   │  TokenTextSplitter
               │                     │  (512 токенов, перекрытие 50)
               └──────────┬──────────┘
                          │  List<Document> (чанки)
                          ▼
               ┌─────────────────────┐
               │  VenueMetadata      │  GPT-4o структурированный вывод
               │  Enricher           │  → вместимость, удобства, контакты
               └──────────┬──────────┘
                          │  List<Document> + метаданные площадки
                          ▼
               ┌─────────────────────┐
               │  EmbeddingModel     │  text-embedding-3-small
               │                     │  (1536 измерений на чанк)
               └──────────┬──────────┘
                          │  List<Document> + float[] эмбеддинги
                          ▼
               ┌─────────────────────┐
               │  TenantAware        │  PostgreSQL + pgvector
               │  PgVectorStore      │  схема на тенанта
               └──────────┬──────────┘
                          │
                          ▼
               ┌─────────────────────┐
               │  MetadataAggregator │ Консолидация на основе событий
               │                     │  (разрешение конфликтов)
               └─────────────────────┘
```

**Эскиз Java-реализации:**

```java
@Service
@RequiredArgsConstructor
public class VenueAssetProcessingPipeline {

  private final TikaDocumentReader.Factory tikaFactory;
  private final TokenTextSplitter splitter;
  private final VenueMetadataEnricher enricher;   // кастомный DocumentTransformer Spring AI
  private final EmbeddingModel embeddingModel;
  private final VectorStore vectorStore;
  private final MetadataAggregationService aggregationService;

  public void process(VenueAsset asset, byte[] content) {
    // 1. Извлечь — Tika обрабатывает PDF, DOCX, XLSX, изображения через OCR, DWG
    var reader = tikaFactory.create(new ByteArrayResource(content), asset.getContentType());
    var rawDocs = reader.get();

    // 2. Обогатить сырые документы исходными метаданными
    var taggedDocs = rawDocs.stream()
      .map(doc -> doc.mutate()
        .metadata("venue_id", asset.getVenueId())
        .metadata("asset_id", asset.getId())
        .metadata("asset_type", asset.getType())
        .metadata("tenant_id", TenantContext.getCurrentTenantId())
        .build())
      .toList();

    // 3. Разбить на семантические чанки
    var chunks = splitter.apply(taggedDocs);

    // 4. Обогатить специфичными для площадки метаданными (структурированный вызов LLM)
    var enrichedChunks = enricher.apply(chunks);

    // 5. Эмбеддинг + запись в pgvector
    vectorStore.add(enrichedChunks);

    // 6. Агрегировать извлечённые метаданные в профиль площадки
    var extractedMetadata = enricher.getLastExtractionResult();
    aggregationService.applyExtractionEvent(asset, extractedMetadata);
  }
}
```

### 2.3 Матрица обработки по типу актива

| Тип актива                        | Парсер                            | Нужен OCR     | Структурированное извлечение | Индекс векторов    |
| --------------------------------- | --------------------------------- | ------------- | ---------------------------- | ------------------ |
| PDF-презентация (текст)           | Tika → ParagraphPdfDocumentReader | Нет           | Да (GPT-4o)                  | Да                 |
| PDF-презентация (отсканированная) | Tika + OCR (Tesseract)            | Да            | Да (GPT-4o)                  | Да                 |
| План этажа (PDF)                  | Docling (с пониманием вёрстки)    | Нет           | Да (зрение GPT-4o)           | Да                 |
| План этажа (изображение)          | Прямое зрение GPT-4o              | Да (LLM)      | Да                           | Да                 |
| Фото                              | Зрение GPT-4o                     | Нет           | Обнаружение удобств          | Да                 |
| DOCX / Техническая спецификация   | TikaDocumentReader                | Нет           | Да (GPT-4o)                  | Да                 |
| XLSX (таблицы вместимости)        | TikaDocumentReader                | Нет           | Структурированный парсинг    | Да                 |
| DWG / DXF (CAD)                   | AutoCAD-парсер Tika               | Нет           | Только метаданные            | Только метаданные  |
| Видео (обзор)                     | Извлечь миниатюру + аудио         | Через Whisper | Частичное                    | Частичное (Фаза 2) |

### 2.4 Стратегия чанкинга

Чанкинг документов значительно влияет на качество извлечения. IQ BENE использует гибридную стратегию:

**Для презентаций площадок (PDF):**

- `ParagraphPdfDocumentReader`: сохраняет структуру параграфов
- Размер чанка: 512 токенов с перекрытием 50 токенов
- Метаданные на чанк: номер страницы, заголовок раздела, ID актива, уровень уверенности

**Для планов этажей (изображения/PDF с диаграммами):**

- Чанкинг на уровне страницы (один Document на страницу)
- Прикрепить полностраничное изображение для обработки зрением GPT-4o
- Извлечь: названия залов, размеры, пометки по вместимости

**Для спецификаций (таблицы):**

- Модель Docling TableFormer восстанавливает ячейки таблицы
- Каждая строка таблицы становится документом с заголовками столбцов как метаданными
- Сохраняет реляционную структуру: `{"room": "Grand Ballroom", "capacity_banquet": 400, "capacity_theater": 600}`

**Для фото:**

- Без текстового чанкинга — передать напрямую в зрение GPT-4o
- Один Document на изображение с извлечёнными зрением метаданными

### 2.5 Почему Apache Tika — правильный фундамент

Apache Tika — проверенный в боях парсер документов экосистемы Java с 2007 года:

- **1000+ форматов файлов** — единый интерфейс независимо от типа файла
- **Tika Pipes** — каждый файл обрабатывается в форкнутом JVM; неправильный или вредоносный файл не может уронить сервис
- **Проверен в производстве** — используется Elasticsearch, Solr, Apache Nutch, корпоративными поисковыми системами по всему миру
- **Поддержка DWG/DXF** — встроенный парсер формата AutoCAD (редкая возможность — большинство альтернатив этого не поддерживают)
- **Прямая интеграция со Spring AI** — `TikaDocumentReader` поставляется с Spring AI, нет необходимости в пользовательском коде
- **Нулевая облачная зависимость** — работает внутри процесса, не требуется вызов API для извлечения текста

**Конфигурация Tika Pipes для производственной безопасности:**

```java
@Bean
public TikaDocumentReader.Factory tikaReaderFactory() {
  return TikaDocumentReader.Factory.builder()
    .withTikaConfig(TikaConfig.getDefaultConfig())
    .withForkParser(true)          // Каждый файл в изолированной JVM
    .withParseTimeout(60)          // Максимум 60 с на файл
    .withMaxMemory(256 * 1024 * 1024)  // 256 МБ на файл
    .build();
}
```

### 2.6 Интеграция Docling для высокоточного парсинга PDF

Для презентаций площадок со сложными вёрстками, таблицами и многоколоночными структурами Docling превосходит базовый парсинг PDF от Tika:

**Когда использовать Docling вместо Tika для PDF:**

- Многоколоночные вёрстки (большинство презентаций площадок)
- Таблицы вместимости (настройки банкет vs. театр vs. классная комната)
- Смешанные текстовые + диаграммные страницы (планы этажей, встроенные в PDF)
- Отсканированные PDF, требующие OCR с пониманием вёрстки

**Подход к интеграции:**

```java
// Кастомный DocumentReader Spring AI, оборачивающий HTTP API Docling
@Component
public class DoclingDocumentReader implements DocumentReader {

  private final DoclingClient doclingClient; // REST-клиент к сервису Docling

  @Override
  public List<Document> get() {
    var doclingResult = doclingClient.convert(resource, ConversionOptions.builder()
      .withTableExtraction(true)
      .withOcr(resource.getContentType().contains("image"))
      .build());

    return doclingResult.getChunks().stream()
      .map(chunk -> Document.builder()
        .content(chunk.getText())
        .metadata("page", chunk.getPage())
        .metadata("element_type", chunk.getType()) // TEXT, TABLE, FIGURE
        .metadata("table_data", chunk.getTableJson())
        .build())
      .toList();
  }
}
```

**Развёртывание Docling (самохостинг, нулевая стоимость):**

```yaml
# добавление в docker-compose.yaml
docling-service:
  image: ds4sd/docling-serve:latest
  ports:
    - "5001:5001"
  environment:
    - DOCLING_WORKER_THREADS=4
```

**IBM Granite-Docling-258M** (выпущен 2026): Сверхкомпактный VLM, который преобразует документы в структурированные форматы, сохраняя вёрстку, таблицы, уравнения. Может заменить тяжёлые ML-модели Docling на более лёгкую конечную точку вывода для развёртываний, чувствительных к стоимости.

### 3.2 Модель метаданных с происхождением и уверенностью

Каждое поле несёт полное происхождение:

  "alternatives": [
    { "value": 480, "confidence": 0.72, "source_type": "FLOOR_PLAN" }
  ],
  "overridden_by": null

Ни один существующий инструмент для площадок не выставляет такой уровень происхождения данных. Пользователи видят не только значение, но и _почему_ система в него верит.

### 3.3 Агрегация из нескольких источников (сложная задача, которую никто не решает)

Площадки присылают одну и ту же площадку в нескольких форматах — маркетинговая презентация, PDF с планом этажа, техническая спецификация, набор фото. Каждый источник может иметь конфликтующие или дополняющие данные.

Движок агрегации IQ BENE:

1. Собирает все события извлечения на площадку (журнал событий)
2. Применяет правила приоритета: `manual_override > verified > high_confidence_AI > low_confidence_AI`
3. Для массивов (удобства, ограничения): объединение множеств с весом по уверенности
4. Выставляет конфликты в UI: «ИИ нашёл два разных значения вместимости — какое правильное?»
5. Позволяет разрешение в один клик

Это подлинный продуктовый ров. Ни одна другая платформа в сфере мероприятий этого не делает.

## 4. Архитектура масштабируемости

### Событийно-управляемая, горизонтально масштабируемая

```
Загрузка → S3 → AssetUploadedEvent → RabbitMQ → N потребителей → Конвейер обработки
                                                    ↑
                                              Масштабировать потребителей
                                              по глубине очереди
```

- Каждое задание извлечения независимо — N воркеров могут работать параллельно
- Приоритетные очереди по уровню тарифа (Enterprise обрабатывается первым)
- Очередь мёртвых писем ловит сбои — автоматический повтора с задержкой
- Нет единой точки отказа в пути обработки

### Стоимостное масштабирование

| Масштаб            | Стоимость ИИ | Инфраструктура                                        |
| ------------------ | ------------ | ----------------------------------------------------- |
| 100 площадок (MVP) | ~$0.10       | Одиночный контейнер                                   |
| 10K площадок       | ~$10         | 2-3 контейнера                                        |
| 1M площадок        | ~$1,000      | Автомасштабируемый, всё ещё управляемый               |
| 100M площадок      | ~$100K       | Оптимизировать более дешёвыми моделями + кэшированием |

При стоимости GPT-4o извлечения + генерации эмбеддингов $0.001/площадку IQ BENE может обработать 1 миллион площадок примерно за $1000 стоимости ИИ. Это не проблема стоимости.

### Масштабирование векторного поиска

pgvector с индексом IVFFlat:

- Семантический поиск менее чем за 10 мс при 1M площадок
- Масштабируется до ~5M векторов на экземпляр перед потребностью в оптимизации (индекс HNSW или облачный Pgvector)
- Мультитенантная изоляция через схема-на-тенанта — нет межтенантных утечек данных

## 6. Открытые вопросы для реализации

- **Docling vs. чистый Tika:** Начать с Tika для скорости MVP. Добавить Docling для Фазы 2, когда станет важна точность планов этажей.
- **Стратегия OCR:** Tika включает Tesseract для базового OCR. Зрение GPT-4o обрабатывает сложные случаи. Порог: если уверенность OCR Tika < 0.7, эскалировать до зрения GPT-4o.
- **CAD-файлы:** Tika извлекает метаданные из DWG/DXF (размеры, слои). Для Фазы 1 выставлять сырые метаданные. Фаза 2: конвертировать в PNG через LibreCAD/ODA, затем зрение GPT-4o для понимания вёрстки.
- **Видео-обзоры:** Вне скоупа Фазы 1. Фаза 2: извлечь ключевые кадры (ffmpeg), запустить зрение GPT-4o на репрезентативных кадрах.
- **Перекрытие чанков:** перекрытие 50 токенов — стандарт. Контент, специфичный для площадок (например, таблицы вместимости), должен использовать меньшие чанки (256 токенов) для сохранения построчной точности.
- **Свежесть эмбеддингов:** Пере-эмбеддинг, когда ручные перезаписи изменяют консолидированные метаданные. Запуск через `MetadataAggregatedEvent`. Не пере-эмбеддинг неизменённых чанков.
