# v0.1 — Foundation + Catalog Core

> **Audience:** Product, engineering.
> **Purpose:** First shippable increment. Establishes the platform foundation, the master venue catalog, tenant venue CRUD, document upload, and basic extraction.

---

## Goal

A planner can create a venue, upload documents, and see a basic profile with extracted fields.

---

## Epics included

- [E1 — Master Venue Catalog](../epics/E1-master-venue-catalog.md) — platform foundation: shared libraries, schema, seed data, admin API, S3 structure, dedup infrastructure.
- [E2 — Tenant Venue Profiles](../epics/E2-tenant-venue-profiles.md) — venue CRUD, document/asset upload, basic profile view.
- [E3 — Document Intelligence (Basic)](../epics/E3-document-intelligence.md) — upload → parse → core field extraction + confidence scores.

## Feature checklist

v0.1 ships **two UI surfaces**, both of which must be covered end-to-end:

- **Tenant app UI** — the planner-facing application for all tenant-scoped operations: venues, documents, profiles.
- **Platform admin UI** — the platform operator console with oversight across all tenants: master catalog entry management.

### Master catalog infrastructure

- [ ] **Platform admin UI:** list, create, view, edit, and delete master venue entries
- [ ] Master catalog is seeded with a curated set of venues for autocomplete suggestions
- [ ] **Tenant app UI:** venue creation suggests matching master venues and supports one-click promotion

### Tenant venue CRUD

- [ ] **Tenant app UI:** planner can create a venue with core fields: name, address, city, capacity, category, one-paragraph summary
- [ ] **Tenant app UI:** planner can view a venue profile page with all core fields rendered
- [ ] **Tenant app UI:** planner can edit the core fields of a venue they own
- [ ] **Tenant app UI:** planner can delete a venue they own and it no longer appears in any list

### Document upload + basic extraction

- [ ] **Tenant app UI:** planner can upload documents (PDF, DOCX, images) to a venue and see them listed on the venue profile
- [ ] Uploaded documents run through the extraction pipeline and extracted text is stored on the venue record
- [ ] **Tenant app UI:** extracted core fields (capacity, address, category, contact) are surfaced on the venue profile
- [ ] **Tenant app UI:** a confidence score is visible alongside each extracted field value

---

## Acceptance criteria

1. A planner can create a venue from scratch or from a master catalog suggestion and see it appear in their tenant app UI venue list.
2. A planner can upload at least one PDF to a venue through the tenant app UI and the extracted text is visible on the venue profile within the documented extraction SLA.
3. A planner can edit a venue's core fields through the tenant app UI and the changes persist and are visible on page reload.
4. A platform admin can create, edit, and delete master venue entries through the platform admin UI.
5. Documents and venues created in one tenant's app UI are not visible to any other tenant, nor exposed in the platform admin UI's tenant-scoped views (tenant isolation verified end-to-end).
