Но главное, что я бы зафиксировал архитектурно: **не привязываться к конкретной библиотеке**. `Parser`-интерфейс + реестр по MIME-типу, и тогда docling (или Unstructured) позже подключается как ещё одна реализация, без переписывания контракта и без переписывания того, что уже лежит в S3.

По твоей таблице — где согласен, где добавлю:

- **pypdf** — да, но это только plain text. Раскладка и таблицы теряются. Годится как fallback, не как основной.
- **pymupdf (fitz)** — технически лучший вариант: одна библиотека даёт текст, таблицы (`page.find_tables()`), извлечение картинок и рендер страницы в bitmap для OCR, и самая быстрая. **Но он AGPL-3.0.** Для закрытого продукта это блокер без коммерческой лицензии — это главный флаг, который надо решить до, а не после.
- **pdfplumber** — согласен, лучший open-source по таблицам с рамками, MIT. Минусы: медленный и прожорливый по памяти на больших PDF, поэтому нужен стриминг во временный файл и лимит по размеру.
- **RapidOCR (ONNX)** — согласен полностью. Без torch, Apache-2.0 + onnxruntime (MIT), на реальных сканах заметно лучше Tesseract, не требует системного бинаря. Tesseract — только fallback.
- **Unstructured** — как основной движок против: тяжёлый граф зависимостей, `strategy="fast"` под капотом всё тот же pdfminer, и релизы ломают API. Но у него ценно другое — **Element-схема** (Title / NarrativeText / Table / ListItem + метаданные). Предлагаю взять схему как наш выходной контракт, а зависимость не тащить.

Что в таблице не учтено, а по MIME-типам каталога оно есть (`application/pdf, image/jpeg, image/png, image/webp, image/tiff, text/plain, application/msword, …docx`):

- **DOCX** → `python-docx` (MIT), напрямую и надёжно.
- **legacy `.doc`** → в чистом Python нормального решения нет. Дефолт: отклонять с явным статусом `unsupported_format` (LibreOffice headless — отдельный тяжёлый путь, не в MVP). Скажи, если не согласен.
- **images (jpeg/png/webp/tiff)** → Pillow + OCR; многостраничный TIFF — постранично.
- **TXT** → passthrough.

И три вещи, которые я бы заложил в дизайн сразу:

1. **Определение digital vs scanned** — OCR вызывается только на страницах, где текстового слоя нет/почти нет. Иначе OCR жрёт CPU на каждом документе зря.

3. **Лимиты как trust boundary** — max bytes / max pages / timeout, иначе один битый PDF положит воркер.
4. Побочно: Helm-лимит 768Mi для OCR-пути мал, нужно ~1.5–2Gi.
