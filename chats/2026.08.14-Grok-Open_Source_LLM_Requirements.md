**1. Master Catalog + Triple Seat**  
Вы говорите, что уже тянете данные Triple Seat. В доках этого нет нигде. Там только:

Жёстко и по делу.

GPT-4o vision — один из самых дорогих кусков в вашем пайплайне. Каждый floor plan / фото / scanned PDF с картинками жрёт токены. Если не резать сейчас — при росте агентств вы просто сольёте маржу.

### 1. Режьте размер и детализацию картинок (самое большое влияние)

- **Никогда не отправляйте оригинал.**  
  Resize до разумного: 1024px по длинной стороне максимум для floor plans, 768–1024 для обычных фото.  
  Большинство venue-фото и планов после 1024px дополнительной полезной информации почти не дают, а токены растут квадратично.

- **detail: low** почти всегда.  
  High detail нужен только когда реально нужна мелкая разметка (точный подсчёт мест, мелкий текст на плане). В 80–90 % случаев low достаточно для capacity, amenities, restrictions.  
  Low = фиксированные ~85 токенов на картинку вместо сотен/тысяч.

- **Crop мусор.**  
  Если на фото 70 % — пустой зал или логотип вендора — обрезайте. Меньше пикселей = меньше токенов.

### 2. Не вызывайте vision, когда можно без него

- Сначала прогоняйте через Tika / обычный OCR / Docling.  
  Если текст уже извлечён нормально — vision не нужен.  
  Vision только на:
  - чистые изображения (JPG/PNG без текста),
  - scanned PDF, где OCR провалился,
  - floor plans, где нужна геометрия/конфигурации.

- Pre-filter: простой классификатор (дешёвый моделью или даже правилами) — «это floor plan / это меню / это обычное фото».  
  Меню и прайсы часто лучше тянуть текстом.

### 3. Дешёвые модели вместо 4o

- Для простых задач (есть ли сцена, бар, количество столов примерно) — **gpt-4o-mini** с vision. Разница в цене в разы, качество на большинстве venue-ассетов приемлемое.
- Для совсем грубой классификации — Claude 3.5 Haiku / Gemini Flash / даже локальные vision-модели (если latency позволяет).
- 4o оставляйте только на сложные floor plans и high-stakes extraction, где ошибка дорого стоит.

### 4. Кэширование и дедуп

- Хешируйте картинку (perceptual hash + размер).  
  Один и тот же floor plan, загруженный 15 агентствами — извлекаете один раз, потом MC_INHERIT / shared cache.
- В master catalog уже есть идея gap-fill. Расширьте: если картинка уже обработана платформой — не гоняйте vision повторно.

### 5. Батчинг и rate control

- Не делайте синхронно по одной картинке.  
  Собирайте очередь, батчите где возможно (OpenAI поддерживает), контролируйте concurrent requests.
- Ставьте жёсткий budget per tenant / per extraction job.  
  Превысил — в human verification или в «low quality» режим.

### 6. Измеряйте, а не гадайте

Сделайте таблицу прямо сейчас:

| Тип ассета        | Avg input tokens | Avg cost $ | % от всех extraction | Можно заменить? |

| Scanned PDF page  |                  |            |                      |                 |
| Menu / price list |                  |            |                      |                 |

Пока этой таблицы нет — вы оптимизируете вслепую.

### Практический порядок действий на ближайшие 2 недели

1. Включить `detail: low` + resize по умолчанию.
2. Добавить pre-check: если Tika/OCR дал нормальный текст — vision пропускаем.
3. Перевести 60–70 % простых кейсов на 4o-mini.
4. Ввести perceptual hash + shared extraction cache.
5. Поставить cost tracking per job (у вас в mi-data-intelligence уже есть ai_cost_tracking — используйте его жёстко).
