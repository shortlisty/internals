**Репозиторий [oiqb/system-design-documentation](https://github.com/Oiqb/system-design-documentation)** — это pre-build design-документация платформы **OiQb** (на базе open-source foundation iQ Key Value). Стадия: pre-launch MVP — дизайн завершён, код ещё не написан. Ветка `dev`, активный автор — dimdnk (Dima Denysenko). Репозиторий проприетарный.

### Что такое OiQb

OiQb — collaborative workspace для event-агентств. Он превращает разрозненные файлы площадок (PDF, планы, фото, спецификации) в структурированную библиотеку, а затем — в интерактивный pitch board для клиента, который заканчивается timestamped, approved спецификацией (Single Source of Truth).

**Два слоя:**

- **Personal Venue Catalog** (data layer) — приватная библиотека площадок агентства с AI-извлечением метаданных и поиском.
- **Digital Sales Room** (output layer) — клиентский interactive pitch board с collaboration и immutable snapshot при approve.

**Целевая аудитория:** event-агентства (5–50 человек), независимые event-менеджеры, корпоративные event-команды (свадьбы, корпоративы, конференции, 50–1000 гостей).

**Проблема:** файлы площадок разбросаны по email, Drive, WhatsApp; сбор pitch’а занимает часы; клиент получает статический PDF; feedback размазан; нет единого источника правды о согласованном.

**Как работает (в одном предложении):**  
OiQb turns venue files into a pitch and a pitch into an approved spec — so event agencies close client briefs in hours, not days.

### Монетизация

- $150/мес за агентство (полная библиотека + pitch board, unlimited team).
- $300/мес для larger teams (priority processing, API, white-label).
- Будущее: venues платят за verified public profile.

### Архитектура (высокоуровнево)

Строится **поверх** iQ Key Value foundation (gateway, IAM, billing, audit, UI, tenancy — без изменений или с минимальными расширениями).

**Новые компоненты:**

- `oiqb-data-intelligence` — domain-agnostic shared library (ETL contracts, provenance, vectors, cost tracking).
- `oiqb-venue-model` — venue-domain shared library (entities, canonical fields, migrations).
- `oiqb-venue-service` — синхронный core (venues, assets, metadata, search, plan enforcement).
- `oiqb-venue-ingestion-worker` — async sidecar (ETL, AI extraction, embeddings, matching). Event-driven, без inbound HTTP.

**Инфраструктура:** существующий PostgreSQL + pgvector + PostGIS; S3; опционально IBM Docling (Phase 2).

**Domain model (ключевые aggregates):**

- `Venue` (с jsonb metadata + provenance, embeddings, PostGIS location).
- `VenueAsset` (PDF, floor plans, photos и т.д.; two-phase presigned upload).
- `ExtractionJob`.
- Metadata events (append-only log для aggregation).
- Platform-level `VenueRegistry` (public schema, seed data, read-only для tenants).
- Phase 2: Venue Groups.

Canonical metadata schema (capacity configurations, catering policy, AV, accessibility, logistics, restrictions, amenities, contacts и т.д.) с версионированием и provenance.

### Intelligence Layer (ETL)

Основан на **Spring AI ETL pipeline**:

```
DocumentReader (Tika / Docling) → DocumentTransformer (splitter + VenueMetadataEnricher на GPT-4o) → Embedding + PgVectorStore → MetadataAggregator
```

- Tika — основной парсер (1000+ форматов, включая DWG).
- GPT-4o structured output для venue-specific extraction.
- Human-in-the-loop verification.
- Conflict resolution и gap-fill из platform registry.
- Hybrid search (keyword + semantic + structured + geo).

### Roadmap & Vision

- North star metric: **Pitch boards approved per team per month**.
- Стратегические ставки: pitch board — buying trigger (не просто каталог); скорость ответа = конкурентное преимущество; immutable snapshot защищает от post-event споров; клиентская сторона — zero onboarding (просто ссылка).
- Out of scope сейчас: booking/payments, marketplace discovery, CRM, event execution tools, полный CAD/video processing (Phase 2+).

Документация очень структурирована: строгие правила в `AGENTS.md` (audience tags, document types, naming, anatomy эпиков/милестоунов/решений, index-first и т.д.). Есть отдельные папки для business (DSR и старый Personal Venue Catalog), platform, roadmap (vision, epics, milestones, decisions).

Если нужно углубиться в конкретный документ (architecture, intelligence, proposal, pitch-mechanics, competitive landscape и т.д.) — скажи, что именно разобрать подробнее.

**Сравнение OiQb и Destinaitor (destinaitor.com)**

### Кратко о каждом

**OiQb** (из репозитория system-design-documentation):  
Приватный collaborative workspace для event-агентств. Агентство загружает свои файлы площадок (PDF, планы, фото) → AI извлекает структурированные данные → получается searchable Personal Venue Catalog → из него генерируется интерактивный Digital Sales Room (pitch board) для клиента → клиент комментирует и одобряет → создаётся immutable timestamped snapshot как Single Source of Truth.

**Destinaitor** (PCMA + dFakto):  
AI-powered SaaS-платформа destination & venue intelligence для business events (MICE). Собирает публичные/партнёрские данные (LLM + Tempest, Simpleview и др.), даёт verified profiles destinations/venues, поиск, сравнение и RFP-matching. Основной фокус — discovery и research destinations/venues. Для destinations/venues — контроль своего data narrative + Verified badge + аналитика. Для event professionals — бесплатный/complimentary доступ к insights.

### Ключевые различия

| Аспект                    | OiQb                                                                                                 | Destinaitor                                                                                        |
| ------------------------- | --------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| **Основная проблема**     | Разрозненные внутренние файлы агентства + отсутствие единого источника правды при согласовании с клиентом | Неэффективный публичный поиск destinations/venues + перегрузка информацией + недоверие к AI-данным |
| **Тип данных**            | Приватные файлы агентства (tenant-owned) + опционально platform registry                                  | Публичные / партнёрские / verified destination & venue data (глобальный каталог)                   |
| **Основной пользователь** | Event-агентства (5–50 чел.) и independent planners, которые уже знают площадки                            | Business events professionals (планеры) + Destinations/Venues/DMO (двусторонняя)                   |
| **Ключевой workflow**     | Ingestion своих файлов → Catalog → Pitch Board → Client approval + snapshot                               | Search / Compare destinations & venues → RFP analysis → Match suggestions                          |
| **Клиентская сторона**    | Интерактивный pitch board без аккаунта (ссылка) + collaboration + immutable approval                      | Нет (фокус на research и discovery для планера, а не на закрытие сделки с конечным клиентом)       |
| **AI-роль**               | ETL + structured extraction из документов агентства (Tika + GPT-4o) + human verification + embeddings     | LLM-поиск + обогащение + matching на основе отраслевых датасетов PCMA                              |
| **Монетизация**           | $150–300/мес с агентства                                                                                  | Complimentary для event professionals; подписка / Verified для destinations & venues               |
| **Масштаб**               | Локальный / city-by-city, cold-start через seed catalog + concierge                                       | Глобальный (1000+ destinations, 208 стран), PCMA-backed                                            |

### Где идеи пересекаются

- Обе используют AI для структурирования venue/destination-данных и ускорения работы event-профессионалов.
- Обе решают проблему «информационного хаоса» и недоверия к данным (OiQb — через provenance + human-in-the-loop; Destinaitor — через Verified badge + PCMA-валидацию).
- Обе хотят стать trusted source of truth (OiQb — на уровне конкретной сделки/спецификации; Destinaitor — на уровне destination/venue profiles).

### Где они почти не пересекаются (главное)

Destinaitor — это **discovery / research / matching tool** (как умный Cvent + AI для destinations). Он помогает найти и сравнить площадки/города, которых планер может ещё не знать.

OiQb — это **private knowledge → client pitch → signed-off spec tool**. Он работает с уже известными агентству площадками (их файлами) и закрывает цикл до approval клиента. В документации OiQb прямо написано, что venue discovery и marketplace — out of scope (Phase 3+ в лучшем случае).

### Стратегический вывод

Это **не прямые конкуренты**, а скорее complementary layers в event-цепочке:

1. Destinaitor / аналоги → discovery новых destinations & venues.
2. OiQb → превращение уже известных (или найденных) площадок в structured private library + быстрый interactive pitch + immutable approval.

OiQb занимает «vacant slot» между venue discovery tools и generic proposal tools (Qwilr, PandaDoc и т.п.), о котором говорится в их market docs. Destinaitor ближе к первой категории (с сильным AI и отраслевым бэкграундом PCMA).

Если OiQb в будущем добавит сильный platform registry / marketplace-слой, пересечение усилится. Пока же позиции разные:  
**Destinaitor** = «найди и оцени destination/venue».  
**OiQb** = «превратить знание агентства в одобренную клиентом спецификацию за часы».

### Вывод по рынку

OiQb занимает именно тот «vacant slot», о котором говорится в их market docs:

- между **venue discovery** (Cvent, Destinaitor, Vendry…)

1. Ingest _своих_ файлов агентства →

4. Client collaboration + immutable approved snapshot.
